# ملاحظات الترقية — RC4 ← 4.1.0

## الخلاصة

الترقية **لا تلمس بيانات المستخدم**. لا تغيير في اسم قاعدة البيانات ولا رقم نسختها
ولا مخازنها ولا مفاتيحها، ولا حذف لأي سجل. يفتح المستخدم التطبيق بعد التحديث
فيجد كلماته وبطاقاته وتقدمه وسجل محاولاته كما هي.

## ما يحدث فعلياً عند أول تشغيل بعد التحديث

| الخطوة | الأثر على البيانات |
|---|---|
| فتح `deutschflow_v2` نسخة 2 | لا شيء — نفس المخطط، لا `onupgradeneeded` |
| قراءة الإعدادات | دمج مع الافتراضيات؛ قيم المستخدم لها الأولوية |
| ترقية مخطط الإعدادات 5 ← 6 | إضافة مفتاحين جديدين بقيم معطّلة فقط |
| `applyPatchesToExistingWords` | كما في RC4 — تصحيحات معتمدة مسبقاً |
| `engineVersion` | كما هو (6). لا إلغاء لجلسة محفوظة |
| سياسة الاحتفاظ | لا تعمل — معطّلة افتراضياً |

### مخطط الإعدادات 5 ← 6

المفتاحان الجديدان فقط:

```
attemptRetentionDays: 0      // صفر = احتفاظ كامل، لا حذف
autoPruneAttempts:    false  // تنظيف تلقائي معطّل
```

الدمج `{...DEFAULT_SETTINGS, ...savedSettings}` يعني أن كل قيمة حفظها المستخدم
تبقى كما هي، والمفتاحان الجديدان يأخذان القيم المعطّلة. `schemaVersion` وحده
يُحدَّث إلى 6.

**مؤكَّد باختبار:** «ترقية مخطط الإعدادات 5 ← 6 تحافظ على اختيارات المستخدم»
و«الترقية لا تحذف أي محاولة قائمة».

### الهجرة من قاعدة النسخة القديمة `german_vocab_std`

منطق الهجرة لم يتغير، مع إصلاح واحد:

- **قبل:** قراءة إعدادات القاعدة القديمة كانت تأخذ سجل `meta` كاملاً
  (`{key, value, updatedAt}`) وتعامله كأنه كائن الإعدادات، فتضيع تفضيلات
  المستخدم بصمت وتعود كلها إلى الافتراضي.
- **بعد:** `unwrapMetaRecord` يتعامل مع الشكلين (سجل ملفوف أو قيمة مباشرة).

هذا الإصلاح **يستعيد** بيانات كانت تُفقد؛ لا يفقد شيئاً. لمن هاجر سابقاً بنسخة
RC4: إعداداته القديمة لن تعود (الهجرة تتم مرة واحدة)، لكن كلماته وتقدمه لم تتأثر
أصلاً — الخلل كان في الإعدادات فقط.

## سياسة الاحتفاظ بسجل المحاولات — قراءة مهمة

مصمَّمة لتكون **آمنة افتراضياً**:

1. `attemptRetentionDays = 0` و`autoPruneAttempts = false` عند التثبيت وعند الترقية.
2. الترقية والإقلاع لا يحذفان أي محاولة مهما بلغ عمرها.
3. التنظيف التلقائي يتطلب **الشرطين معاً**: تفعيل المفتاح **و** مدة أكبر من صفر.
4. التنظيف اليدوي (زر في الإعدادات):
   - يعرض عدد المحاولات القابلة للحذف قبل التأكيد،
   - ينزّل ملف JSON كاملاً (كلمات + بطاقات + محاولات + إعدادات) قبل الحذف،
   - يحفظ لقطة داخلية في `meta.prePruneSnapshot`،
   - يحذف من مخزن `attempts` فقط.
5. الكلمات والبطاقات والتقدم والإعدادات لا تتأثر إطلاقاً.

للاستعادة بعد تنظيف غير مقصود: استخدم ملف JSON المنزَّل عبر «استعادة نسخة».

## سلوك التحديث بعد هذه النسخة

الإصدار السابق (RC4) كان يستدعي `skipWaiting()` عند التثبيت، أي أن عامل الخدمة
الجديد يستولي على الصفحة فوراً وقد يخلط ملفات نسختين أثناء جلسة جارية.

من 4.1.0 فصاعداً:

1. يُثبَّت العامل الجديد ويبقى في حالة `waiting`.
2. `DF.Update` يرفض التفعيل ما دامت `state.session` موجودة وغير منتهية.
3. بعد انتهاء الجلسة (أو الخروج منها، أو عند الإقلاع خارج جلسة) يظهر شريط تحديث.
4. الضغط على «تحديث الآن» يرسل `SKIP_WAITING` ثم تُعاد الصفحة تلقائياً.

**حالة واحدة خارج السيطرة:** لو أغلق المستخدم كل تبويبات التطبيق أثناء جلسة،
فسيفعّل المتصفح العامل المنتظر عند الفتح التالي. هذا سلوك قياسي لا يمكن منعه،
وهو غير ضار: الجلسة محفوظة في `meta.session` وتُستأنف من نفس الموضع.

**ملاحظة انتقالية:** المستخدم القادم من RC4 سيمر بتحديث واحد أخير بالسلوك القديم
(عامل RC4 هو من يتحكم في تلك اللحظة). ابتداءً من النسخة التالية يعمل المسار الآمن.

## النشر

### البناء المقسّم (موصى به)

ارفع محتوى المجلد كما هو مع الحفاظ على البنية:

```
index.html  version.js  sw.js  styles.css  manifest.webmanifest
icon-192.png  icon-512.png  icon-512-maskable.png  apple-touch-icon.png
data/seed-data.js
src/{core,db,learning,io,ui,controller,register-sw}.js
```

كل المسارات نسبية، فيعمل على `https://example.com/` وعلى
`https://user.github.io/deutschflow/` دون تعديل.

**شرط:** HTTPS (أو `localhost`) — عامل الخدمة لا يعمل بدونه، ولا يعمل عبر `file://`.

### الملف الواحد

`deploy/standalone-index.html` (586 كيلوبايت) يعمل بفتحه مباشرة، حتى من `file://`.
لا يسجّل عامل خدمة ولا يُثبَّت كتطبيق PWA، لكنه يحفظ البيانات في IndexedDB عادياً.
مناسب للنسخ الاحتياطي السريع أو للتشغيل دون استضافة.

لإعادة بنائه بعد أي تعديل: `npm run build`.

### ترتيب العمل الموصى به

```
npm install      # مرة واحدة (fake-indexeddb للاختبارات فقط)
npm run check    # فحص صياغة كل الملفات
npm test         # 82 اختباراً
npm run build    # إعادة بناء الملف الواحد
```

## ⚠ ما لم يُختبر على جهاز حقيقي

**لم يُجرَ أي اختبار على iPhone فعلي.** كل النتائج المرفقة من بيئة Node مع
محاكاة IndexedDB. البنود التالية تحتاج تحققاً يدوياً على الجهاز:

- [ ] تثبيت جديد من Safari على iPhone وإضافته إلى الشاشة الرئيسية
- [ ] الإقلاع في وضع الطيران بعد أول تحميل (**الإصلاح الأهم في هذه النسخة**)
- [ ] الإغلاق والفتح ثم استئناف جلسة غير مكتملة
- [ ] ظهور شريط التحديث بعد رفع نسخة جديدة، وعدم ظهوره أثناء جلسة
- [ ] تنزيل ملف النسخة الاحتياطية واستعادته من Safari على iOS
- [ ] استيراد XLSX على Safari 16.4+، ورسالة الخطأ على إصدار أقدم
- [ ] جلسة طويلة (100+ سؤال) ومراقبة استهلاك الذاكرة
- [ ] عرض النص الألماني LTR داخل الواجهة العربية RTL على شاشة الهاتف
- [ ] لوحة المفاتيح العربية والألمانية داخل حقول الإجابة

كذلك لم يُختبر: التحديث الفعلي لعامل الخدمة في متصفح حقيقي (اختبارات Node تفحص
المنطق والبنية، لا دورة حياة `ServiceWorkerRegistration`)، ولا الأداء الفعلي
لصفحة إدارة الكلمات مع 10,000 مدخل.
